当前阶段：计划已落地，尚未开始 DDL、业务代码、页面和数据迁移

## 文档目标

统一 ERP、WMS 和管理前端的库存预占业务，使每一笔预占都能回答：

- 哪个业务产生。
- 哪一张业务单、哪一个商品明细。
- 从哪些库存取得、取得顺序是什么。
- 预占多少、实际使用多少、释放多少、直接从可用库存扣减多少。
- 谁创建、谁负责、何时到期、提醒了谁。
- 最终是发货消费、取消释放、人工释放还是历史迁移处理。

本文只规划两个库存预占来源：

1. `PACKING_TASK`：赛狐装箱任务。
2. `STOCK_TRANSFER`：库存调拨。

FBA货件、拣货单、发货单、库存冻结不再形成独立的库存预占来源。

当前守恒公式：

```text
库存总量 = 可用库存 + 预占库存
预占数量 = 已消费数量 + 已释放数量 + 剩余预占数量
生命周期关闭 => 剩余预占数量 = 0
```

### 1.2 当前实现中需要纠正的流程

#### 旧 FBA 预占流程错误

当前 ERP 存在以 FBA 货件、FBA shipment item 或 stock move 为预占来源的实现。这是后置业务提前承担库存所有权，流程方向错误。

正确流程：

```text
赛狐装箱任务
  -> ERP/WMS读取同一任务
  -> 装箱任务确认选择库存
  -> 建立装箱任务库存预占
  -> 拣货、装箱、称重
  -> 确认发货并结算装箱预占
  -> 创建或关联FBA货件
```

FBA货件只保存发货结果和原装箱任务关联，不再建立、增加、释放或消费独立预占。

#### 旧库存冻结概念错误

“库存冻结、锁定库存、库存占用”过去混合表达“这批库存已经被业务使用，其他业务不能再动”。

3.0统一规则：

- 物流库存统一称为“库存预占”。
- 不再存在独立库存冻结来源。
- 独立冻结/解冻入口停止新建并进入退役。
- 历史冻结记录逐条核对归属，不能直接批量释放。
- MES物料冻结等非物流库存业务不在本次范围。

#### 旧跨仓调拨结算时点错误

来源仓预占不能一直保留到目标仓收货。

正确流程：

```text
提交调拨 -> 来源仓预占
确认发货 -> 来源仓预占结算并扣减来源仓库存
运输途中 -> 只记录调拨在途数量
确认收货 -> 按实收量增加目标仓库存，不建立预占
```

### 1.4 当前风险

- ERP、WMS以不同业务对象建立重复预占。
- FBA、装箱、拣货或发货各自维护所有权，造成同一批库存多次计算。
- 实际发货少于预占时，余量未及时释放。
- 实际发货大于预占时，直接扣可用库存但没有与原业务统一留痕。
- 历史库存冻结、FBA绑定无法证明真实业务来源。
- 旧固定仓库快照已过期，不能作为本次迁移预期值。
- ERP、WMS都能操作时，缺少统一命令和版本控制会产生并发覆盖。

## 2. 规划现状

### 2.1 统一术语

> 库存预占：某个明确业务暂时保留一批库存，使其他业务不能使用；业务实际发生时优先使用预占，未使用部分恢复可用，超出预占部分再从合格可用库存扣减。

统一中文：

- 库存预占
- 预占量
- 增加预占
- 释放预占
- 消费预占
- 剩余预占
- 预占周期
- 超时预占
- 历史隔离预占

旧“锁定库存、占用库存、物流冻结库存”文案全部迁移为上述名称。

### 2.2 唯一业务来源

#### A. 赛狐装箱任务

业务身份：

- 唯一来源系统：赛狐。
- ERP、WMS都是同一任务的读取和执行端。
- 业务主键：赛狐装箱任务号。
- 商品行主键：赛狐装箱任务商品明细号。
- 同一任务允许多个预占周期。

建立预占：

- 用户在 ERP 或 WMS 确认选择库存时建立。
- 初始预占量为装箱任务计划发货总件数。
- 同一商品允许拆分多笔库存。
- 整张任务只能使用同一仓库、同一库存所属人的库存。
- 每笔库存保存选择顺序。

责任人：

- 主责任人是赛狐装箱任务创建人。
- 无法映射到 ERP/WMS 用户时仍允许建立预占。
- 此时预占进入“责任人待认领”，由库存管理员认领。

库存换绑：

- 先校验新库存。
- 新库存全部满足后，在同一事务释放旧预占并建立新预占。
- 任一步失败，旧预占和新库存都不变化。

赛狐数量同步：

- 数量减少：自动释放差额。
- 数量增加：优先增加原选择库存的预占。
- 原库存不足：保持已有预占，记录待补数量并产生告警。
- 后续增减不重置本周期到期时间。
- 发货完成后赛狐再变化：不回滚库存，只记录来源变更异常。

流程回退：

- 未确认发货前，无论待拣货还是已拣货，都视为库存仍在原库区。
- 已拣货退回待拣货：保留预占。
- 待拣货退回装箱任务：释放全部剩余预占。
- 赛狐取消或删除任务：立即释放全部剩余预占并关闭。

重新选择：

- 一个周期全部释放后保持关闭。
- 同一任务重新选择库存时建立下一预占周期。
- 关闭周期禁止重新打开。

#### B. 库存调拨

业务身份：

- ERP、WMS均可发起。
- 使用一个全局唯一、双方共享的调拨单号。
- 双方操作同一调拨单，不复制调拨生命周期。

建立预占：

- 调拨申请提交时建立来源仓预占。
- 责任人是调拨申请人。
- 驳回或发货前取消时释放全部预占。

发货前改量：

- 减少计划量：自动释放差额。
- 增加计划量：尝试增加原来源库存预占。
- 来源库存不足：保留原预占并产生待补库存告警。

确认发货：

- 以确认发货时提交的实际发货量为准。
- 发货时立即结算来源预占并减少来源仓总库存。
- 发货后剩余预占必须为零。
- 在途数量只存在于调拨业务，不属于仓库预占。

收货：

- 目标仓按实际收货量增加可用库存和总库存。
- 收货不建立预占。
- 实收量与发货量不一致时记录调拨差异。
- 确认实收后原调拨单完成，不等待差异处理后再关闭。

撤销与反向：

- 发货后、收货前撤销：执行原发货的反向库存事件，恢复来源仓库存，不重建预占。
- 收货完成后需要撤回：新建目标仓到来源仓的反向调拨。
- 原调拨历史不得覆盖或删除。

### 2.3 一次发货结算规则

装箱任务和库存调拨均只允许一次确认发货并结清当前预占。

```text
R = 当前剩余预占量
A = 确认发货实际数量

使用预占量 = MIN(A, R)
释放预占量 = MAX(R - A, 0)
直接扣可用量 = MAX(A - R, 0)

发货后：
剩余预占量 = 0
可用库存变化 = 释放预占量 - 直接扣可用量
预占库存变化 = -R
总库存变化 = -A
```

场景：

| 场景 | 处理 |
| --- | --- |
| A = R | 全部消费预占，总库存减少A |
| A < R | 消费A，释放R-A，总库存减少A |
| A > R | 先消费R，再从原选择库存的可用量扣A-R |
| A > R + 合格可用量 | 整次发货失败，库存和预占都不变化 |

多笔库存规则：

- 按原选择顺序消费。
- 实际量满足后，后续库存剩余预占全部释放。
- 超发部分仍按原选择库存顺序使用当前可用量。
- 不自动搜索未被本业务选择的其他库存。
- 不允许跨仓库或跨库存所属人补扣。

发货门禁：

- 必须至少存在一笔有效预占。
- 业务状态允许发货。
- 所有预占明细、库存余额、WMS库存分解必须守恒。
- 实际数量必须为正。
- 合格可用库存足够覆盖超发部分。
- 发货结算、释放余量、扣减库存、流水、事件和命令必须同事务成功。

### 2.4 生命周期与数据模型

#### `erp_stock_reservation`

一条记录表示一张业务单的一个预占周期。

主要数据：

- 预占单号。
- 业务类型：PACKING_TASK / STOCK_TRANSFER。
- 业务单号、业务主键、周期号。
- 创建端、创建人。
- 当前责任人。
- 仓库、库存所属人。
- 状态和关闭原因。
- 第一次预占时间、到期时间、关闭时间。
- 计划数量、预占总量、消费总量、释放总量、剩余总量。
- 待补库存数量。
- 来源快照、迁移证据、版本。

业务唯一键：

```text
PACKING_TASK  = 赛狐装箱任务号 + 周期号
STOCK_TRANSFER = 全局调拨单号
```

#### `erp_stock_reservation_item`

一条记录表示一个业务商品明细选择的一笔库存。

主要数据：

- 预占周期。
- 业务商品明细号。
- ERP库存ID。
- 仓库和库存所属人快照。
- SKU、商品、批次快照。
- 选择顺序。
- 预占量、消费量、释放量、剩余量。
- 待补量。
- 状态、版本和来源指纹。

始终满足：

```text
reserved_qty = consumed_qty + released_qty + remaining_qty
```

#### `erp_stock_reservation_event`

不可覆盖的生命周期时间线：

- 创建预占。
- 增加/减少预占。
- 库存换绑。
- 赛狐数量同步。
- 待补库存告警。
- 确认发货。
- 消费预占。
- 释放余量。
- 直接扣可用库存。
- 业务取消。
- 人工释放。
- 责任人认领。
- 发货撤销补偿。
- 调拨收货和实收差异。
- FBA关联。
- 来源变更异常。
- 提醒发送和已知晓。
- 历史迁移基线、认领和受控释放。

#### `erp_stock_reservation_command*`

ERP、WMS共享幂等命令：

- namespace、commandId。
- action。
- 业务和预占周期。
- 请求指纹。
- 预期版本。
- 操作人来源、ID、名称。
- 每笔库存的动作数量。
- 库存流水引用。
- 执行结果和执行后剩余量。

同一命令：

- 同key同指纹成功重放：返回原结果。
- 同key不同指纹：拒绝。
- 版本冲突：整次失败并要求刷新。
- 失败事务不得留下部分成功。

#### `erp_stock_reservation_allocation`

- 保存WMS库存分解。
- 不形成第二套预占所有权。
- item剩余量必须等于其allocation剩余量之和。
- 未发货前不因待拣货/已拣货建立新的暂存区库存。

#### `erp_stock_reservation_policy`

只维护两条业务类型规则：

- PACKING_TASK。
- STOCK_TRANSFER。

配置：

- 天数。
- 小时数：0–23。
- 总时长必须大于0。
- 是否启用。
- ERP系统管理员维护。
- WMS只读。
- 修改只影响新预占周期。

#### `erp_stock_reservation_reminder`

保存：

- 预占周期。
- 责任人。
- 提醒日期。
- ERP/WMS待办状态。
- 钉钉发送状态。
- 重试次数和错误。
- 已知晓时间和操作人。

规则：

- 装箱任务从该周期第一次预占开始整单计时。
- 调拨从申请提交建立预占时计时。
- 到期当天发送提醒。
- 之后每天发送一次，直到预占结清。
- “我已知晓”只留记录，不停止提醒。
- 不升级到直属负责人。
- 无责任人时进入待认领异常。

### 2.5 状态

| 状态 | 含义 |
| --- | --- |
| ACTIVE | 有剩余预占，尚未发生消费或释放 |
| PARTIALLY_SETTLED | 有剩余预占，已发生部分释放或调整 |
| WAITING_STOCK | 计划量增加但原库存不足，保留已有预占并等待补库存 |
| RELEASED | 预占全部释放，未发生实际出库 |
| CONSUMED | 全部预占用于实际发货，无释放余量 |
| MIXED_CLOSED | 一部分用于发货，一部分释放 |
| ORPHANED | 历史来源不明确，禁止普通消费和释放 |

关闭状态永久保留，禁止删除或重新打开。

### 3.7 验收场景

#### 装箱

- 精确发货。
- 少发并释放余量。
- 超发并从原选择库存扣可用量。
- 超发库存不足，整次失败。
- 多笔库存按选择顺序消费。
- 原子换绑。
- 赛狐增量、减量和取消。
- 待补库存。
- 已拣退待拣保留预占。
- 退回装箱任务释放。
- 全部释放后建立新周期。
- 发货后赛狐变化只记异常。

#### 调拨

- ERP/WMS任一端发起同一调拨单。
- 提交建立预占。
- 发货前改量。
- 精确、少发、超发和库存不足。
- 发货时来源仓扣减并结束预占。
- 按实收量入库。
- 实收差异。
- 发货后收货前撤销恢复来源库存。
- 收货后通过反向调拨撤回。

#### 提醒

- 两类业务分别配置。
- 0天0小时被拒绝。
- 到期当天提醒。
- 每日重复提醒。
- 已知晓后继续提醒。
- 责任人待认领。
- 配置变更只影响新周期。

#### 历史

- 旧FBA唯一关联装箱任务。
- 旧FBA无法关联进入隔离。
- 旧冻结归属装箱/调拨。
- 无证据冻结不自动释放。
- 所有逐stock、item、allocation守恒。
