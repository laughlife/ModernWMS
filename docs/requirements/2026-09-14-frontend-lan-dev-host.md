# 前端开发环境局域网访问修复需求

- 需求日期：2026-09-14
- 原始目标：修复 ModernWMS 前端开发环境只能通过 127.0.0.1 访问、局域网其他设备无法访问的问题。
- 目标仓库：`D:\\ai-dev\\ModernWMS`
- 关联项目：无。本任务仅维护 ModernWMS，`ruoyi-vue-pro` 与 `yudao-ui-admin-vue3` 不在本次范围内。

## 背景与现状

ModernWMS 的 Vite 开发服务已配置为监听所有网卡并固定使用前端端口 81；统一开发启动脚本还会显式覆盖 Vite 的 API 基址。当前配置存在三处不一致：

1. `scripts\\Watch-Backend.ps1` 将 `VITE_BASE_PATH` 强制设置为 `http://127.0.0.1`，导致局域网浏览器把 API 请求发往访问者自己的回环地址。
2. `frontend\\.env.development` 和 `backend\\ModernWMS\\appsettings.Development.json` 仍使用旧的局域网地址 `192.168.100.102`，与本机实际地址 `192.168.100.2` 不一致。
3. 开发 CORS 允许列表缺少本机地址 `http://192.168.100.2:81`（启动脚本和开发配置均需保持一致）。

## 本次范围

- 修改 `frontend\\.env.development` 的开发 API 基址为 `http://192.168.100.2`。
- 修改 `scripts\\Watch-Backend.ps1`，让统一启动器向 Vite 注入 `http://192.168.100.2`，并允许该地址的前端来源；保留 localhost 和 127.0.0.1 访问兼容性。
- 修改 `backend\\ModernWMS\\appsettings.Development.json` 的开发 CORS 地址，将旧地址替换为 `192.168.100.2`。
- 如静态核对确认 IDE 启动配置仍绑定回环地址，则同步调整 `backend\\ModernWMS\\Properties\\launchSettings.json` 的开发监听地址，确保不使用统一启动器时后端也可被局域网访问。
- 更新 `docs\\development.md` 中与开发访问地址、端口和 CORS 规则相关的说明，使文档与实际配置一致。

## 非范围与约束

- 不修改 ModernWMS 业务功能、接口契约、数据库表、数据库列、初始化数据或生产环境配置。
- 不修改 `D:\\ai-dev\\ruoyi-vue-pro`、`D:\\ai-dev\\yudao-ui-admin-vue3` 或其他仓库。
- 不启动或重启开发服务，不执行测试、构建、类型检查、Lint、浏览器或 E2E 验证；本任务按 ModernWMS 静态验收门禁执行。
- 保留现有工作区中与本任务无关的修改和暂存删除。

## 预期行为

- 在本机启动开发环境后，前端可通过 `http://192.168.100.2:81` 访问。
- 从局域网其他设备打开该地址时，前端请求发送到 `http://192.168.100.2:21011`，不会解析为访问设备自己的 `127.0.0.1`。
- 后端允许来源 `http://192.168.100.2:81`；本机已有 `localhost` 和 `127.0.0.1` 地址继续可用。
- Vite 继续监听 `0.0.0.0`/所有网卡，端口仍为 81；后端统一启动器继续监听 `0.0.0.0:21011`。

## 验收标准

1. 静态搜索显示开发环境和统一启动器不再把 `VITE_BASE_PATH` 指向 `127.0.0.1` 或旧地址 `192.168.100.102`。
2. 静态配置同时包含 `192.168.100.2` 的前端开发地址和对应 CORS 允许来源。
3. `git diff --check` 对本次修改文件无空白错误，且提交只包含本需求拥有的文件。
4. 记录本地提交哈希，并明确运行时验证未执行。

## 优先级与风险

- 优先级：高。局域网联调无法进行会阻断前端协作。
- 主要风险：本机 IP 变化后需同步更新开发配置；防火墙仍可能阻止 81/21011 端口（本次不修改系统防火墙）。
- 回滚方式：回滚本需求对应的本地提交即可恢复原开发地址。
