# 装箱任务驱动的发货工作流设计

## 背景与目标

当前发货流程需要承接 SellFox 装箱任务和 WMS 现场作业。
用户可选择多个同仓 SellFox 装箱任务生成一张新的 WMS 拣货单，每个装箱任务又包含多个物理箱。
SellFox 装箱任务是拣货单的唯一业务来源，不经过 FBA 或 ERP 发货单号创建。
现有页面若直接按商品明细或箱子展开，会造成拣货单重复、任务边界不清、称重状态难以汇总。

本设计目标如下：

- 在 WMS 中建立真正的拣货主单，并以装箱任务作为拣货、称重、出库的作业边界。
- 保留外部来源数据的可追溯性，同时明确 WMS 现场测量值的唯一权威地位。
- 让装箱任务来源页按 SellFox 任务逐行多选，后五个作业页面按一张 WMS 拣货单展示一行。
- 统一状态、事务、幂等、权限和打印规则，为后续 SellFox 回写预留稳定扩展点。

## 已确认业务规则

1. 用户选择一个或多个 SellFox 装箱任务生成一张 WMS 拣货单。
2. 一张拣货单内所有装箱任务必须属于同一仓库；发现跨仓选择时整批拒绝，不创建部分单据。
3. 一张拣货单可关联一个或多个装箱任务，装箱任务是唯一来源和稳定幂等边界。
4. 商品行按装箱任务保留；即使 SKU 相同，也不得跨装箱任务合并作业行。
5. 装箱任务是拣货、称重完成判断和后续回写的最小业务单元。
6. 物理箱是重量和尺寸测量的最小数据单元，且必须归属一个装箱任务。
7. 创建待拣货单时不校验、不分配库存。
8. 人工点击“拣货完成”时才重读库存、执行分配并校验充分性。
9. 任一商品库存不足时整单保持 `PENDING_PICK`，不产生部分成功的库存分配。
10. 拣货主单只能沿既定状态链前进，不允许页面直接跨状态修改。
11. `PENDING_PICK` 期间的列表、详情、打印和人工“拣货完成”都必须先读取 XXL 维护的本地共享数据库表，并对账最新有效装箱任务。
12. ModernWMS 绝不直接调用 SellFox HTTP；SellFox 数据只通过 XXL 落地的本地共享表进入本流程。
13. 待拣货打印前必须完成对账，打印不改变状态。
14. WMS 仓库测量值是重量和尺寸的唯一事实来源。
15. 外部箱数据不得覆盖已经产生的 WMS 测量值。
16. 称重箱集合严格等于当前有效任务 `cartons_json` 中的来源箱集合，WMS 不得新增来源之外的箱。
17. 复制功能只把已有实测值复制到另一个已存在的目标来源箱，复制后允许逐箱编辑。

## 选型

### 真正主单与关联表

采用“真正主单 + 装箱任务关联表”方案。
`wms_dispatch_order` 保存 WMS 拣货主单级身份、仓库、状态和来源快照信息。
`wms_dispatch_packing_task` 保存主单与外部装箱任务之间的一对多关系。
已有发货明细不再直接代表一个页面主单，而是通过装箱任务归属到主单。

该方案避免使用重复明细模拟主单，也避免把多个任务号拼接后作为数据库主键。
主单编号、任务编号和物理箱编号分别承担不同层级的稳定身份。

### SellFox 箱身份与 WMS 测量来源

SellFox `cartons_json` 用于识别来源箱及其标签等外部属性。
系统必须验证并保留来源箱的稳定标识，数组位置不能静默充当长期箱身份。
若实施前无法验证稳定箱 ID，称重入口必须失败关闭并记录可诊断错误，不允许进入箱测量。
稳定箱 ID 能力验证是上线称重功能前的必做数据能力检查。
来源箱身份只用于匹配和追溯，不作为重量、尺寸的权威来源。

采用严格方案 A：一个有效装箱任务可称重的箱集合只能由其当前 `cartons_json` 建立。
WMS 既不能手工新增箱，也不能通过复制操作创建箱；来源集合以外的箱身份一律拒绝。

重量和长宽高必须来自 WMS 仓库现场测量。
SellFox 提供的重量或尺寸可留作只读来源快照或差异提示，但不得写入实测字段。

## 数据模型

### `wms_dispatch_order`

建议核心字段：

- `id`：WMS 内部主键。
- `dispatch_no`：WMS 拣货主单号，唯一。
- `warehouse_id`：作业仓库。
- `status`：主单状态。
- `source_version`：最近一次来源对账版本或摘要。
- `source_snapshot`：主单级来源只读快照。
- `source_change_pending`：来源变化待裁决冻结标志。
- `source_change_snapshot`：触发裁决的来源差异快照。
- `accepted_source_version`：人工继续发货已接受的来源版本或摘要。
- `adjudicated_source_version`：最近一次人工裁决对应的来源版本或摘要。
- `adjudicated_by`、`adjudicated_at`、`adjudication_reason`：人工裁决审计字段。
- `created_at`、`updated_at`、`row_version`：审计与并发控制字段。

主单创建请求以排序后的 SellFox 装箱任务稳定身份集合生成幂等键，防止同一批任务重复建单。
数据库必须约束一个有效装箱任务只能属于一张未取消的 WMS 拣货单。
主单状态由所有任务的作业结果汇总驱动，不由前端任意赋值。

### `wms_dispatch_packing_task`

建议核心字段：

- `id`：WMS 内部主键。
- `dispatch_order_id`：所属 WMS 拣货主单。
- `task_no`：WMS 展示的装箱任务号。
- `source_task_id`、`source_task_no`：外部任务身份。
- `source_cartons_json`：SellFox 箱来源快照。
- `status`：任务状态，可与主单状态分层汇总。
- `measured_box_count`、`expected_box_count`：完成判断所需计数。
- `source_version`、`updated_at`、`row_version`：对账和并发字段。

`source_task_id` 在有效任务关系中建立唯一约束，`dispatch_order_id + source_task_id` 作为关系幂等约束。
任务号用于展示和检索，不代替内部主键。

### 已有发货明细按任务关联

已有 dispatch detail 增加或使用 `packing_task_id` 外键。
每条商品明细必须明确属于一个装箱任务。
同一 SKU 分布在多个任务时，必须保留多条任务级明细，不跨任务合并作业数量。
主单级汇总可聚合展示，但拣货确认必须落到任务明细。

### 库存分配

创建 `PENDING_PICK` 主单时只保存来源任务和商品行，不读取、不校验、不分配库存。
人工点击“拣货完成”时，在一个事务中重读当前库存并执行充分性校验与分配。
库存分配记录关联发货明细，并可反向确定装箱任务和主单。
分配需记录仓库、库位、库存批次、SKU、分配数量和已拣数量。
重复请求使用业务幂等键，不得重复占用库存。
若任一明细库存不足，整个事务回滚，主单保持 `PENDING_PICK`，不保留部分分配。
分配全部成功后才完成拣货事实并迁移到 `PICKED`。

### 通用称重箱模型

采用可复用的通用称重箱实体，例如 `wms_weighing_box`。
每个称重箱必须通过 `packing_task_id` 直接归属一个装箱任务；通用扩展字段不能替代该强制归属。

建议字段包括：

- `box_identity`：WMS 稳定箱身份。
- `source_box_identity`：SellFox 稳定来源箱身份，必填。
- `box_sequence`：任务内箱序号。
- `weight`、`length`、`width`、`height`：WMS 实测值。
- `measurement_status`：未测量、已测量。
- `measured_by`、`measured_at`：测量审计。
- `copied_from_box_id`：复制来源，可空。
- `source_snapshot`：外部箱只读快照。
- `row_version`：并发控制。

实测字段不得由来源对账更新。
复制测量值时必须指定同一有效装箱任务中已存在的目标来源箱。
复制只更新目标箱的重量和尺寸并标记复制来源，不创建新箱；操作员可随后逐箱修改。

## 状态流转

主流程固定为：

`PENDING_PICK → PICKED → WEIGHING → PENDING_OUTBOUND → OUTBOUND`

- `PENDING_PICK`：主单已创建，允许来源对账、打印和拣货准备，尚未分配库存。
- `PICKED`：所有任务的要求数量已完成拣货，库存事实已确认。
- `WEIGHING`：进入逐箱测量，允许测量、编辑，或在已有来源箱之间复制实测值，不允许新增箱。
- `PENDING_OUTBOUND`：所有任务的全部物理箱均已测量并通过校验，等待出库确认。
- `OUTBOUND`：库存出库和业务完成事务已提交，业务数据只读。

状态迁移必须由后端校验前置条件，并记录操作人、时间和迁移原因。
`PENDING_PICK → PICKED` 仅由人工“拣货完成”触发，并在同一事务内完成库存重读、充分性校验和分配。
库存不足时不得迁移状态，也不得保留部分库存结果。
任何任务未完成时，主单不得进入下一阶段。
一个装箱任务的全部物理箱均完成 WMS 实测并通过校验后，该任务才算称重完成。
只有主单下全部装箱任务都称重完成，主单才允许从 `WEIGHING` 迁移到 `PENDING_OUTBOUND`。
不支持回退时应返回明确业务错误；确需冲正时另建受审计的冲正流程。

异常终态包括 `SOURCE_CANCELLED` 和 `MANUAL_CANCELLED`。
`SOURCE_CANCELLED` 表示待拣货阶段全部来源任务已取消；`MANUAL_CANCELLED` 表示拣货后经人工裁决取消发货。

## 来源对账

ModernWMS 的来源读取点是 XXL 维护的本地共享数据库表，不直接访问 SellFox HTTP。
主单处于 `PENDING_PICK` 时，列表、详情、打印和人工“拣货完成”均须先读取共享表中的最新有效任务并执行对账。
对账以 SellFox 装箱任务身份和稳定来源箱身份进行匹配，不使用 FBA 或 ERP 发货单号。
对账必须再次验证所有有效装箱任务同仓；出现跨仓数据时整单报错，不做部分更新。

待拣货期间商品或数量发生修改时，按装箱任务边界重建该任务的商品明细，同 SKU 不跨任务合并。
人工“拣货完成”必须使用本次对账后的最新商品与数量，再读取、校验和分配库存。
单个来源任务取消时，将该任务从主单的有效任务集合移除，并释放其尚未实际出库的库存分配；其他有效任务继续保留。
全部来源任务取消时，主单进入 `SOURCE_CANCELLED`，并从待拣货列表消失。
任务移除、分配释放和主单状态更新必须原子提交，取消记录保留审计。

状态达到 `PICKED` 且尚未 `OUTBOUND` 时，来源修改或取消不得自动改变既有 WMS 商品、库存或测量事实。
系统设置 `source_change_pending`，保存差异快照，并冻结该主单的称重和出库操作。
人工必须选择“继续发货”或“取消发货”，同时记录裁决人、时间和原因。
选择继续发货时，接受当前 WMS 快照作为本单后续事实并解除冻结，不用来源变化覆盖它；同时记录 `accepted_source_version`、差异摘要、操作人、时间和原因。
同一已接受来源版本或摘要不得重复触发冻结；只有检测到后续更高版本或不同摘要时才再次设置 `source_change_pending`。
选择取消发货时，记录裁决来源版本、差异摘要、操作人、时间和原因，原子释放尚未实际出库的库存分配，逻辑作废后续测量事实但完整保留审计，主单进入 `MANUAL_CANCELLED`。
主单已经 `OUTBOUND` 后发现来源修改或取消时，仅记录来源异常，不自动取消或改写实际出库事实。

对账写入来源版本或内容摘要；相同版本重复请求直接返回已有结果。
对账失败不得留下半更新数据，也不得覆盖 WMS 实测字段。

## 待拣货打印

打印发生在 `PENDING_PICK` 阶段。
每次打印请求先读取 XXL 维护的本地共享数据库表，对账该主单关联的最新有效装箱任务，再返回请求时刻的完整展开数据。
打印按“WMS 拣货主单 → 装箱任务 → 商品明细”完整展开，不以物理箱作为待拣货打印单位。
完整展开数据包含主单、全部有效装箱任务和各任务商品行，保持任务边界。
对账与打印数据组装成功后一次性返回；失败时不返回不完整结果。
打印操作不改变主单状态，不触发库存校验或分配。
本期不要求追踪打印后的线下单据去向，也不强制把打印时间或模板版本记录为业务事实。

## 仓库权限

Admin 可选择全部仓库，进入页面时默认选中 ERP 仓库 `320118`。
普通角色只能访问新增角色-仓库绑定关系中明确授权的仓库，不提供默认 `320118` 权限。
新增角色-仓库关联模型，例如 `wms_role_warehouse(role_id, warehouse_id)`，并建立唯一约束。
权限接口提供当前用户可见仓库列表；Admin 返回全部仓库并携带默认仓库提示，普通角色返回授权并集。
角色维护接口负责查询和更新仓库绑定，更新时校验仓库有效性并在事务内整体替换。
不将普通角色仓库列表硬编码到页面。
所有查询、详情、操作和打印接口均由后端执行仓库权限过滤。

本流程不引入商品租户隔离。
商品、SKU 和库存的可见性以仓库权限和业务状态为边界。
现有 `tenant_id` 仅可为技术兼容保留，不能参与决定仓库可见性或商品业务隔离。
前端隐藏按钮仅用于体验优化，不构成安全控制。

## 六个页面行为

六个页面准确为：装箱任务、待拣货、已拣货、称重、待出库、已出库。
装箱任务是来源选择页，必须一条可选 SellFox 装箱任务一行，并支持多选后生成 WMS 待拣货单。
装箱任务一旦成功生成待拣货单，即从可选来源列表移除，不再作为可重复选择项展示。
装箱任务页的分页、计数、勾选和批量生成均以 SellFox 装箱任务稳定身份为单位。

只有待拣货、已拣货、称重、待出库、已出库五个页面采用“一张 WMS 拣货单一行”的展示规则。
后五页同一主单的多个装箱任务号在任务号列中以标签、换行或可展开列表展示。
后五页的分页、计数、勾选和批量操作均以主单 `id` 为单位。

详情页按“主单 → 装箱任务 → 商品明细/物理箱”分层展开。
拣货操作进入任务级明细，但完成状态回写并汇总到主单行。
称重操作先选择任务，再对该任务的物理箱逐箱测量或复制。
待出库与已出库页面仍保持主单一行，不因箱数或任务数复制行。
装箱任务页按来源任务号等来源条件搜索；后五页支持 WMS 拣货单号和任一 SellFox 装箱任务号命中同一主单。
任务状态存在差异时，主单行显示最早未完成阶段，并可展开查看差异。

## 事务、幂等与错误规则

主单创建、同仓校验、任务关联和明细落库应在一个事务内完成，创建阶段不处理库存。
状态迁移必须同时校验当前状态、任务完成度、库存结果和箱测量完整性。
待拣货列表与详情在返回前执行共享表读取和最新有效任务对账，任何对账失败均返回一致性错误，不返回新旧混合数据。
人工“拣货完成”须先完成共享表读取与对账，再将最新明细的库存重读、充分性校验、库存分配和状态迁移放在一个事务内完成。
事务提交前必须校验来源版本未变化，避免对账与库存分配之间出现竞态。

主单从 `PICKED` 到 `OUTBOUND` 之前，以下每个入口都必须在各自事务开头读取 XXL 本地共享表并检测来源版本或内容摘要：

- 进入称重。
- 保存箱测量。
- 完成单个装箱任务称重。
- 整单转入 `PENDING_OUTBOUND`。
- 确认出库。

若入口检测到尚未裁决的新版本差异，必须在该事务内写入差异摘要并设置 `source_change_pending`，提交冻结状态但不提交任何称重或出库推进，随后返回业务拒绝。
版本检测以 `accepted_source_version` 和最近裁决版本消重；同一已接受版本直接通过，只有更高版本或不同摘要才重新冻结。
人工继续或取消裁决必须以来源版本和主单为幂等边界，重复请求返回既有裁决结果，不得重复解除、冻结或释放库存。
出库事务需原子完成库存扣减、分配关闭、状态更新和操作日志。

建单幂等键使用排序后的 SellFox 装箱任务稳定身份集合。
任务幂等键使用 WMS 主单与 SellFox 装箱任务稳定身份。
物理箱幂等键使用装箱任务与稳定来源箱身份，且该身份必须存在于当前有效 `cartons_json`。
测量提交可使用箱身份与请求幂等键，重复提交返回同一结果。
来源差异事件以主单和来源版本或摘要建立消重约束，防止同一版本重复冻结。

并发更新使用 `row_version` 或等价乐观锁。
版本冲突返回可识别的冲突错误，引导刷新，不静默覆盖。
业务校验错误应区分权限不足、状态不允许、库存不足、箱未测完、来源差异和来源变化待裁决。
ModernWMS 不存在 SellFox HTTP 可用性依赖；共享数据库读取失败或一致性对账失败时，拒绝待拣货打印并返回明确错误。
所有异常均保留关联主单、任务、箱和请求幂等键，便于审计追踪。
