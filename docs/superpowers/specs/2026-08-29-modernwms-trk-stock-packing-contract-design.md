# ModernWMS `trk_stock` 装箱库存主合同设计

## 1. 目标

ModernWMS 的装箱库存生命周期以 `trk_stock.id` 作为唯一库存身份，彻底移除租户、库存新旧模式、仓库维护门槛、第二套仓库业务编号和位置分配对装箱绑定的依赖。

本设计覆盖候选查询、绑定、初始预占、增减预占、换绑、取消、释放、实际装箱调整、拣货承接和出库结算，并同步修改 ModernWMS 前端选择库存界面、Flyway 前向迁移、手工回退方案、自动化测试和真实接口验证。

## 2. 已确认约束

- 装箱任务创建人必须唯一解析为 `system_users.id`。
- 候选库存只允许 `trk_stock.order_user_id` 等于任务创建人用户 ID，且 `trk_stock.warehouse_id` 等于装箱任务 `warehouse_id`。
- 管理人员可以代操作，但业务库存归属仍是任务创建人，不能绑定操作者或其他下属的库存。
- 同创建人、同仓的全部 `trk_stock` 商品均可选择；商品编码匹配项优先，其他商品不得隐藏或禁选。
- 候选、绑定、预占、调整、换绑、取消和释放均不依赖库区、库位、`wms_erp_stock_allocation` 或任何位置分配。
- 初次绑定数量仍按“装箱任务量 × 变体数量”计算。
- 库存不足、超计划和负库存不得新增阻断；实际装箱事实优先于计划数量。
- `SHIP_OUT` 成功后不可原地回退；拦截退回必须形成新的入库事实。
- ModernWMS 与 ERP 后端不通过 HTTP 互调，但必须维护一致的装箱库存业务规则和共享数据库事实。
- `192.168.100.2` 是获准读写的开发测试库，可用于迁移演练和真实接口测试；生产库禁止连接、读取或写入。
- 只修改 ModernWMS 仓库；其他 ERP 仓库如需实施，另行建立 Handoff。

## 3. 非目标

- 不重新设计实际装箱阶段的多货主业务。
- 不处理历史签收入库库存迁移。
- 不恢复或新增 ModernWMS 与 ERP 后端之间的 HTTP 集成。
- 不修改 FBA 自动消费和历史订单收尾规则。
- 不在本任务中物理删除仍承载库内作业或历史释放的数据表；只形成有证据的后续清理清单。

## 4. 当前问题

当前实现存在以下不符合目标合同的行为：

- `PrelockReservationOwnersAsync` 在校验仓库 ID 后无条件抛出“批量预锁包含跨租户预占来源”。
- 装箱任务查询根据 `LEGACY_READ`、`CANONICAL_ERP` 和 `maintenance_enabled` 分流或拒绝。
- 候选查询依赖 `wms_warehouse.erp_warehouse_id`、`wms_erp_stock_allocation`、库区、库位和 WMS 货主映射。
- 前端提供“搜索其他库存”、位置和所属人筛选，并允许确认后选择他人库存。
- 绑定、释放、实际装箱、拣货和出库把 `stock_allocation_id` 当作必填身份。
- 共享预占在 `wms_erp_stock_reservation_allocation` 中按位置分配二次拆分，导致没有位置分配的 `trk_stock` 无法进入生命周期。
- 部分生产代码及错误文案仍包含租户语义。

## 5. 核心领域合同

### 5.1 库存身份

新装箱链只使用 `trk_stock.id` 作为库存身份。装箱相关业务表中的 `erp_stock_id` 直接引用该 ID。

`stock_id` 仅代表历史 `wms_stock.id`，`stock_allocation_id` 仅代表历史位置分配。两者不得出现在新绑定 API 的必填合同、候选资格判断、幂等身份或新写路径中。

### 5.2 创建人解析

服务端按装箱任务 `create_name` 精确匹配有效的 `system_users.nickname`：

- 恰好一条有效用户：使用该用户 `id` 作为任务库存所有人 ID。
- 没有匹配：返回明确业务错误，不返回候选。
- 多条匹配：返回“创建人无法唯一解析”的业务错误，不选择任意用户。
- 不允许退化为名称包含匹配、WMS 货主名称匹配或当前操作者 ID。

### 5.3 仓库身份

Sellfox 装箱任务、`erp_warehouse` 和 `trk_stock` 的 `warehouse_id` 属于同一业务 ID 域。装箱链直接比较任务 `warehouse_id` 与库存 `warehouse_id`。

`wms_warehouse.id` 可以继续作为库区、库位层级的内部技术主键，但 `wms_warehouse.erp_warehouse_id` 不再是装箱候选、绑定或库存变更的前置映射条件。

### 5.4 候选集合与排序

候选基础条件固定为：

```text
trk_stock.deleted = 0
AND trk_stock.order_user_id = resolved_task_owner_user_id
AND trk_stock.warehouse_id = packing_task.warehouse_id
```

不得加入以下硬过滤：

- 任务商品 SKU 相同；
- 可用量大于零；
- 存在 WMS SKU 映射；
- 存在 WMS 货主映射；
- 存在 `wms_erp_stock_allocation`；
- 存在库区或库位；
- 运行模式或仓库维护状态。

商品匹配只影响排序和标签。匹配规则沿用任务商品编码与库存 `commodity_sku` 去除变体后缀后的比较。排序依次为：已选择、商品匹配、`trk_stock.id`。

关键词搜索仅在已经满足同创建人、同仓硬边界的候选集合内按商品编码、商品名称等字段过滤，不能扩大数据范围。

## 6. API 合同

### 6.1 候选请求

候选请求保留：

- `sellfox_task_id`
- `sellfox_item_id`
- `page_index`
- `page_size`
- `keyword`

删除：

- `search_others`
- `location`
- `owner`

### 6.2 候选响应

新响应以库存事实为中心，包含：

- `selection_id`：已有活动绑定的生命周期 ID，没有绑定时为空；
- `erp_stock_id`：`trk_stock.id`；
- `commodity_id`；
- `commodity_sku`；
- `commodity_name`；
- `main_image`；
- `order_user_id`；
- `order_user_name`；
- `warehouse_id`；
- `warehouse_name`；
- `total_qty`；
- `available_qty`；
- `occupied_qty`；
- `matched`；
- `selected`；
- `selected_qty`。

新响应不暴露装箱绑定所不需要的位置筛选字段。历史兼容数据不得借候选接口暴露其他创建人或其他仓库的库存。

### 6.3 绑定与调整请求

新绑定请求包含：

- `sellfox_task_id`
- `sellfox_item_id`
- `erp_stock_id`
- `variant`

服务端根据最新任务量计算目标预占数量，不信任客户端传入的数量、创建人、仓库或位置字段。

更新已有绑定时，以任务明细、`erp_stock_id` 和活动选择记录确定生命周期；取消优先使用 `selection_id` 精确定位，并再次校验任务与库存快照。

## 7. 事务与安全校验

所有绑定写操作在一个数据库事务中完成，锁顺序固定为：

1. 装箱任务及任务明细；
2. 创建人解析结果；
3. 共享预占主单与明细；
4. `trk_stock`；
5. 本地选择和幂等操作记录。

在持有锁后重新校验：

- 任务仍有效且未取消；
- 任务创建人仍唯一对应同一用户；
- `trk_stock.order_user_id` 仍等于任务创建人用户 ID；
- `trk_stock.warehouse_id` 仍等于任务仓库 ID；
- 库存未被逻辑删除。

任何校验失败都回滚整个事务。禁止通过前端隐藏代替服务端校验。

## 8. 预占和库存变更

### 8.1 新写路径

共享预占主单和明细继续使用：

- `trk_stock_reservation`
- `trk_stock_reservation_item`
- `trk_stock_reservation_command`
- `trk_stock_reservation_command_item`

`trk_stock_reservation_item.stock_id` 直接引用 `trk_stock.id`，其数量字段承载预占、释放、消费和剩余数量守恒。

新装箱操作不再创建或更新 `wms_erp_stock_reservation_allocation` 的位置分解行，不再要求 `allocation_id` 参与共享命令指纹。

`trk_stock` 更新规则保持库存数量守恒：

- 预占：`available_qty -= qty`，`occupied_qty += qty`，`total_qty` 不变；
- 释放：`available_qty += qty`，`occupied_qty -= qty`，`total_qty` 不变；
- 出库消费：`occupied_qty -= qty`，`total_qty -= qty`；
- 调整或超额实际装箱：允许 `available_qty` 或 `total_qty` 进入业务允许的负数范围，但 `occupied_qty` 不得因释放或消费变为负数。

每次变更写入 `trk_stock_record`，记录操作键、业务类型、任务/明细、库存 ID、前后数量、预占命令和操作人。

### 8.2 幂等

操作键由动作、任务 ID、任务明细 ID、`erp_stock_id`、旧数量、新数量和序列组成。位置分配 ID 不再参与新命令身份。

同一操作键重复请求必须返回原成功结果；操作键对应的请求指纹不同则拒绝。

### 8.3 换绑

换绑在单一事务内完成：先锁定原预占所有人和新预占所有人，再锁定两个 `trk_stock`，释放原库存并预占新库存，最后更新选择记录。任何一步失败都整体回滚。

## 9. 历史兼容

历史选择可能同时包含 `stock_id`、`erp_stock_id` 和 `stock_allocation_id`。兼容策略是：

- 新候选和新绑定永远不生成位置依赖。
- 历史活动选择仍可取消、释放或由装箱差异结算处理。
- 历史释放优先使用已有 `reservation_id`、`reservation_item_id` 和 `erp_stock_id` 更新共享预占及 `trk_stock`。
- 只有确实存在旧位置分解余额时，兼容适配器才同步结清 `wms_erp_stock_reservation_allocation` 与 `wms_erp_stock_allocation`；该同步不能成为主释放成功的候选门槛。
- 历史兼容路径不得创建新的位置分配或新的位置级预占行。
- 无法安全解析 `erp_stock_id` 的纯 `wms_stock` 历史行不自动猜测映射，写入清理报告并由后续受控数据任务处理。

## 10. 实际装箱、拣货和出库

装箱选择转入拣货、称重箱明细和实际装箱结算时，业务分组键由 `stock_allocation_id` 改为 `erp_stock_id`。相关表的 `stock_allocation_id`、`goods_location_id`、`goods_owner_id` 和 WMS SKU 映射字段转为历史兼容快照，不再作为新行必填。

新行需要保存 `commodity_id`、`commodity_sku`、`commodity_name`、`order_user_id` 和 `erp_stock_id` 快照，以支持没有 WMS SKU、货主或位置映射的 `trk_stock`。

实际装箱仍允许任务外商品和数量差异。确认后按实际明细增占、减占、换绑、释放或消费；库存不足不阻断称重与发货。`SHIP_OUT` 成功后禁止恢复原预占或改写原出库流水。

## 11. 删除库存模式和维护门槛

删除所有生产代码、DTO、实体、前端类型、SQL 查询和错误文案中的：

- `LEGACY_READ`
- `CANONICAL_ERP`
- `maintenance_enabled`
- `wms_inventory_runtime_config` 读取和写入
- “旧库存模式”“统一库存模式”“库存维护窗口”等运行门槛语义

装箱和统一库存服务不再按仓库路由两套读写实现。仍需支持的历史读取通过明确的历史兼容适配器完成，不再称为库存模式，也不由运行配置切换。

`wms_inventory_runtime_config` 在前向迁移中删除。相关实体、策略类和测试替换为“生产代码不存在运行模式依赖”的架构合同测试。

## 12. 前端设计

ModernWMS 选择库存弹窗：

- 删除“搜索其他库存”按钮和状态；
- 删除位置、所属人筛选；
- 删除库位/所属人列和跨创建人确认框；
- 保留商品关键词搜索；
- 显示任务仓库和任务创建人；
- 显示库存商品、总量、可用量、占用量；
- 已绑定行优先，其次显示匹配商品，再显示其他可选商品；
- 对非匹配商品显示“其他商品”标签，但选择按钮保持可用；
- 删除前端“可用量不足”阻断，数量由服务端按业务合同处理；
- 行身份统一为 `erp_stock_id`，不再使用 legacy/allocation 分支。

## 13. 去租户收尾

生产程序集不得包含租户类型、成员、参数、SQL 条件、写入字段或中文跨租户错误文案。

现有 `V20260827090000__remove_tenant_dependencies.sql` 继续作为物理删列迁移。已在任何环境执行过的 Flyway 版本文件遵守不可变规则，不修改校验和；新迁移不得新增或写入 `tenant_id`。

尚未执行的手工切换脚本中包含的租户、模式和维护门槛逻辑必须删除或以明确的历史归档说明退出可执行路径。

## 14. 数据库迁移

新增前向迁移负责：

- 删除 `wms_inventory_runtime_config`；
- 使装箱选择、拣货、称重箱明细、库存操作中的位置兼容列可空；
- 为 `erp_stock_id` 建立必要的活动选择、查询和业务幂等索引；
- 使新库存操作记录允许 `allocation_id` 为空；
- 为实际装箱行补充直接商品和库存所有人快照字段；
- 删除只服务运行模式、维护门槛或新装箱位置身份的约束和索引；
- 保留历史位置分配表及旧行，供只读和释放兼容；
- 在迁移前用查询检测去掉位置身份后可能冲突的活动业务键，存在冲突时明确失败，不静默合并生产数据。

迁移不会在生产库执行。本任务只在 `192.168.100.2` 开发测试库完成前向迁移、真实业务回归和回退演练。

## 15. 回退方案

Flyway 版本迁移不修改历史文件，回退以独立、人工评审的 SQL 脚本交付。回退顺序为：

1. 停止新版本写流量；
2. 确认不存在未结算的新式 `erp_stock_id` 绑定；
3. 备份本任务涉及表；
4. 恢复兼容列约束、索引和运行配置表结构；
5. 只对能从历史快照唯一还原的位置字段进行回填；
6. 无法还原位置的新式绑定必须先释放或由人工迁移，禁止伪造库区、库位；
7. 部署旧应用版本；
8. 执行数量守恒和活动预占核对。

回退脚本不恢复租户列，不允许回到租户模型。运行模式表的重建仅用于应用版本回退兼容，不能作为未来业务方案。

## 16. 数据库表清理报告

最终交付必须按以下类别列出相关表、代码引用、读写证据和建议：

1. **当前主链必需**：新装箱绑定、共享预占、库存余额和流水仍持续读写的表。
2. **仓内其他业务仍使用**：装箱不再依赖，但入库、库区、库位、冻结、移库、盘点等模块仍使用的表。
3. **仅历史兼容**：新代码不再新写，只为旧选择、旧位置分配或旧流水读取/释放保留的表。
4. **可后续删除**：生产代码、迁移、接口和前端均不再引用，并完成数据归档与数量核对后可物理删除的表。
5. **本次已删除**：由前向迁移直接删除且无业务数据保留价值的表。

每个“可后续删除”表必须附前置条件、数据备份要求、引用扫描证据和建议删除顺序。本任务不擅自删除仍含历史业务数据的表。

## 17. 测试策略

### 17.1 回归与单元测试

- 先新增能复现 `PrelockReservationOwnersAsync` 无条件异常的失败测试，再修复。
- 创建人唯一解析：唯一、缺失、重名。
- 候选硬边界：同人同仓可见；他人、他仓不可见。
- 商品排序：匹配项优先，其他商品仍可选择。
- 没有位置分配、WMS SKU 或货主映射的 `trk_stock` 可绑定。
- 初次预占、增占、减占、换绑、取消、释放和重复请求幂等。
- 负库存和超计划不新增阻断。
- 历史 allocation 选择仍能释放，但不产生新位置分配。
- SHIP_OUT 不可逆和实际装箱差异规则保持。

### 17.2 架构与迁移合同测试

- 生产程序集不包含 tenant 依赖或租户错误文案。
- 生产代码不包含运行模式、维护门槛或运行配置表引用。
- 新绑定 API 和前端类型不包含 `search_others`、位置筛选或必填 allocation 身份。
- 新迁移不写 `tenant_id`，删除运行配置表并正确调整兼容列。
- 前向迁移和回退脚本在开发测试库演练后结构和数据守恒检查通过。

### 17.3 构建与真实接口验证

- 运行聚焦后端测试和完整后端解决方案构建。
- 运行前端单元测试、类型检查和生产构建。
- 在 `192.168.100.2` 校验目标主机后启动临时 ModernWMS 服务。
- 使用真实登录、候选查询、绑定、调整、换绑、取消和释放接口验证开发测试数据。
- 验证完成后清理测试业务数据和临时服务，不清理用户既有数据。
- 检查日志不存在 `operation_failed`、跨租户、库存模式、维护窗口或位置缺失异常。
- 记录命令、接口结果摘要、日志路径、构建结果和数据库守恒查询证据。

## 18. 发布与验证顺序

1. 合并并发布 ModernWMS 代码和前端构建产物前，先完成开发测试库迁移演练。
2. 生产迁移必须另行审批、备份和核对目标主机；本任务不连接生产库。

5. 其他 ERP 仓库根据最终字段合同在独立 Handoff 中对齐。

## 19. 验收标准

- 无条件跨租户异常有红绿回归证据并已修复。
- 生产程序集与新迁移合同没有租户业务依赖或 `tenant_id` 新写。
- 同人同仓全部商品可见，匹配优先，其他商品可选，他人他仓不可见。
- 无库区、库位和位置分配的 `trk_stock` 完成全生命周期验证。
- 装箱和统一库存链不读取运行配置或仓库维护状态。
- 新选择、共享预占和库存流水直接引用 `trk_stock.id` 并保持数量守恒。
- 前端不提供跨创建人或位置筛选入口。
- 聚焦测试、完整后端构建、前端测试和生产构建通过。
- 开发测试库真实接口与日志验证通过；生产库未连接、未读取、未写入。
- 交付迁移、回退、最终字段合同、提交号和数据库表清理报告。
