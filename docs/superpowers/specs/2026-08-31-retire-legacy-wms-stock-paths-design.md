# 旧 WMS 库存路径下线设计

## 背景

测试库已经备份并删除 `wms_stock` 与 `wms_stock_record`。当前库存余额和库存流水以
`trk_stock`、`trk_stock_record` 为准，但 ModernWMS 仍有旧收货、移库、冻结、盘点、
调整、加工和旧出库兼容代码直接访问已删除的两张表。只要这些分支被调用，就会出现
数据库表不存在错误。

本阶段只清理旧路径，不提前实现各功能的新库存流程。收货、移库、冻结、盘点、调整和
加工将在后续任务中逐个迁移。

## 目标

- 生产运行时代码不再查询、写入或映射 `wms_stock`、`wms_stock_record`。
- 已经存在 ERP 库存实现的操作继续使用 `trk_stock` 及当前仓储分配、预占和流水模型。
- 尚未迁移的旧操作保留现有接口和页面，调用时返回清晰的中文停用提示，不出现数据库
  异常，也不静默成功。
- 不改变装箱、拣货、称重、发货当前使用的 ERP 库存主链。
- 不删除 `wms_erp_stock_allocation`、`wms_erp_stock_reservation_allocation`、
  `wms_erp_stock_allocation_log`、`wms_inventory_operation` 或装箱选择表。

## 实施边界

### 已有新路径的功能

移库、冻结、盘点、调整和加工服务中，已经具备 `erp_stock_id`、
`stock_allocation_id` 以及统一库存变更服务的分支。清理时：

1. 要求操作记录具备 ERP 库存身份。
2. 删除对旧库存表的备用查询、更新和插入分支。
3. 缺少 ERP 库存身份时，在发生任何库存写入前返回中文停用提示。
4. 保留当前业务单据表及其状态，不在本阶段迁移历史单据。

### 尚无新路径的功能

旧 ASN 收货确认只会写入 `wms_stock`，本阶段不临时拼接新的收货逻辑。接口继续存在，
确认操作返回“旧收货功能已停用，请使用 ERP 待收货功能”。查询历史页面和非库存写入
能力在不访问已删除表时继续保留；任何需要旧库存表才能完成的操作一律返回停用提示。

### 出库兼容逻辑

装箱任务的新出库流程继续使用 ERP 库存和共享预占。旧发货单中直接扣减或回补
`wms_stock` 的兼容分支全部停止执行：

- 能识别为 ERP 库存的明细继续走现有统一库存路径。
- 只具备旧库存身份的明细返回中文停用提示。
- 删除旧库存流水写入、旧库存数量扣减和旧库存回补代码。

### 库位与实体清理

- 库位删除校验只检查仍然存在的 ERP 仓储分配关系，不再访问 `wms_stock`。
- 删除只服务于 `wms_stock_record` 的数据库实体；其他可能仍被请求模型或历史单据使用的
  类型只有在确认无引用时才删除。
- Flyway 基线和历史迁移保持不可变。本阶段不再次执行数据库删除，也不自动操作备份表；
  当前测试库的恢复来源仍是 `bak_wms_stock_20260831` 和
  `bak_wms_stock_record_20260831`。

## 接口与错误处理

接口路径暂时保持不变，避免旧前端调用变成无法识别的 404。尚未迁移的操作统一遵循：

- 返回失败，不更新业务状态和库存数据。
- 文案直接说明具体功能已停用并提示后续使用 ERP 库存新路径。
- 不使用内部英文状态值作为用户提示。
- 不把缺表异常、SQL 或堆栈信息返回前端。

页面按钮本阶段不统一删除。后续改造某个功能时，再同时调整该功能的前端交互、接口契约
和权限。

## 跨仓库影响

只读核对显示，`ruoyi-vue-pro` 当前装箱库存代码不直接访问 `wms_stock` 或
`wms_stock_record`；ERP 管理前端、XXL-JOB 和 FBA 同步仓库也没有这两张表的运行时依赖。
本阶段代码修改归属 ModernWMS，不需要修改其他仓库。

## 验收方式

按用户要求，不采用测试驱动，也不执行自动化测试。完成时只做：

1. 静态搜索确认生产运行时代码对两张旧表零引用。
2. 编译 ModernWMS 后端，确认清理未造成编译错误。
3. 检查 Git 差异，确认没有夹带现有工作区中的其他修改。

功能行为由用户后续按模块逐项验证。

## 后续顺序

旧路径清理完成后，每个功能单独确认业务规则、实现新路径并由用户验证。建议顺序为：

1. 收货。
2. 库存调整。
3. 移库。
4. 冻结与解冻。
5. 盘点。
6. 加工。
7. 旧发货单兼容入口的最终移除。
