# 装箱草稿与按任务量称重设计

## 目标与边界

本设计替代 `2026-08-15-packing-task-dispatch-workflow-design.md` 中“箱集合必须来自 SellFox `cartons_json`、WMS 不得新增箱”的称重方案，其余装箱任务、拣货、出库边界保持不变。

- 一条装箱任务独立完成装箱与称重，不与其他装箱任务混装，即使创建人相同也不例外。
- 同一装箱任务内的所有商品均可混装进任意一个或多个 WMS 实体箱。
- 箱内商品数量统一使用任务量单位。二变体任务量 100 的装箱上限是 100，不是商品需求量 200。
- 商品需求量继续展示，并作为库存锁定、释放和最终扣减的商品件数口径。
- WMS 现场创建实体箱、分配箱内商品、填写箱规和重量；全部完成后才允许进入待出库。

## 数量口径

每条任务商品同时保留三类数量：

- `task_qty`：装箱任务量，是箱内分配与装箱完成判断的唯一口径。
- `required_qty`：商品需求量，是库存锁定、释放和出库扣减口径。
- `packed_task_qty`：按箱内分配汇总出的实际装箱任务量。

变体数量在创建 WMS 拣货单、快照装箱任务商品时一并固化为 `variant_qty`。称重页面直接只读展示该值，不允许重新输入，也不在称重阶段通过 SKU 文本或两个数量临时推算。例如任务量 100、变体 2，商品需求量自动展示为 200；实际装箱 95 个任务单位时，实际占用库存自动计算为 190 件，释放 10 件库存。

创建任务商品快照时必须验证 `task_qty > 0`、`variant_qty > 0`，并保证 `required_qty = task_qty × variant_qty`。称重阶段只使用已固化的 `variant_qty` 做自动展示和库存换算；快照关系异常时拒绝保存装箱方案并返回明确业务错误，不使用四舍五入修正库存。

同一商品在所有有效箱中的分配数量之和不得超过当前可装任务量。不同商品分别校验，不能用一种商品的余量抵扣另一种商品。

## 数据模型

通过 Flyway `V3` 追加迁移，不改写历史 FBA 表。

### 装箱任务状态字段

在 `wms_dispatch_packing_task` 追加：

- `packing_plan_status`：`DRAFT`、`ACTUAL_CONFIRMED`、`COMPLETED`。
- `actual_confirmed_at`、`actual_confirmed_by`、`actual_confirmed_by_name`：按实际装箱确认审计。

订单仍保持现有 `WEIGHING` 状态。草稿是任务级装箱方案状态，不增加新的订单页签状态。

### 商品实际装箱字段

在 `wms_dispatch_packing_task_item` 追加：

- `variant_qty`：创建装箱任务/拣货单时固化的变体数量，称重页面只读展示。
- `actual_packed_task_qty`：确认后的实际装箱任务量，可空；草稿阶段由箱内明细实时汇总。
- `actual_packed_required_qty`：按变体比例换算后的实际商品件数，可空。

来源快照中的 `source_quantity_shipped` 和 `required_qty` 不被覆盖，保证计划值与实际值可同时审计。
已有新流程数据在迁移中按已保存的 `required_qty / source_quantity_shipped` 做一次确定性回填；无法形成正整数变体的数据标记为异常并禁止进入装箱保存，不静默写成默认值。

### WMS 实体箱

继续使用 `wms_weighing_box`，但箱集合改由 WMS 管理：

- 新建箱时生成不可变 `box_identity`，`source_box_identity` 使用 WMS 任务号和箱序号形成的展示身份。
- 支持草稿阶段新增、编辑和逻辑删除箱子。
- `weight`、`length`、`width`、`height` 允许草稿阶段为空；完成时四项必须全部大于 0。
- 被逻辑删除的箱子不参与数量和完成判断，保留审计记录。

### 箱内商品明细

新增 `wms_weighing_box_item`：

- `id`、`weighing_box_id`、`packing_task_item_id`。
- `task_qty`：该商品在该箱中的任务量单位数量，必须为正整数。
- `create_time`、`last_update_time`、`row_version`。
- 唯一约束 `(weighing_box_id, packing_task_item_id)`。

后端必须验证箱与商品属于同一有效装箱任务，禁止通过直接请求跨任务混装。

## 页面交互

称重一级页面按 WMS 拣货单展示白色主表，并与待拣货、已拣货保持一致，直接展开只读商品详情：图片、商品信息/SKU、FNSKU/MSKU、任务量、商品需求量和可用量快照。建箱、商品分配、箱规和重量等可编辑内容不直接展示；每个装箱任务在操作列只保留一个“建立装箱并称重”入口，点击后打开宽屏白色弹窗。

弹窗内先完整展示该装箱任务的商品池，字段包括图片、商品信息、FNSKU/MSKU、变体、任务量、自动计算的商品需求量、已分配任务量、剩余任务量。商品行不设置独立建箱按钮；操作员通过统一“新增箱”创建箱子，再把同任务的任意商品加入箱内混装。

每个箱卡片提供：

- 箱号与删除箱功能。
- 同任务商品选择和各商品任务量输入；变体、箱内商品件数等其余数量只读自动展示。
- 重量、长、宽、高输入。
- 箱内任务量合计和字段完整状态。

页面提供三个明确动作：

1. `新增箱`：创建空箱，并从该装箱任务的完整商品池中选择商品混装。
2. `保存`：保存当前箱集合、商品分配、箱规和重量；允许商品未分完、箱规未填完、重量未填，但不释放任何库存。页面不展示“草稿”字样，确定装箱完成前均可继续修改、删除箱或移除箱内商品。
3. `确定装箱完成`：要求所有有效箱均已填写完整箱规和重量，汇总每种商品的未装任务量与待释放商品件数并弹窗逐项提示；用户确认后释放剩余库存、固化实际数量并完成当前装箱任务。确认后不再允许修改或删除。

当至少存在一个有效箱、每个有效箱至少有一条商品且重量和长宽高全部大于 0 时，`确定装箱完成`才可点击。未装完的商品在确认弹窗中明确列出并释放余量；当前任务完成后，全部装箱任务均完成的订单进入待出库。

## 保存草稿事务

保存接口接收完整任务级草稿快照，而不是逐字段零散写入。事务内执行：

1. 锁定订单、装箱任务、任务商品、当前有效箱和箱内商品行。
2. 校验订单为 `WEIGHING`、来源未冻结、`row_version` 一致。
3. 校验所有箱和商品都属于当前任务，箱内数量为正整数，逐商品汇总不超过允许上限。
4. 新增或更新提交的箱和箱内商品，对未提交的旧草稿箱逻辑作废。
5. 保持 `packing_plan_status=DRAFT`，不修改库存分配数量。
6. 写入操作账本并递增版本，重复请求返回同一结果。

草稿允许不完整，但不允许负数、零数量明细、跨任务商品、重复商品行或超过任务量。

## 按实际装箱确认与库存释放

确认接口在一个串行化事务内完成数量固化与库存释放：

1. 重新校验草稿汇总，至少存在一个有效箱和一条箱内商品。
2. 按商品计算 `actual_packed_task_qty`，再用创建时固化的 `variant_qty` 自动计算 `actual_packed_required_qty`。
3. 对现有 `wms_dispatchlist` 和 `wms_dispatchpicklist` 分配执行缩减。优先保留原分配顺序，按分配记录倒序释放尾部数量；只减少尚未出库的 `pick_qty`、`picked_qty`、`qty`、`lock_qty` 等对应锁定事实，不直接修改 `wms_stock.qty`。
4. 各分配行缩减总量必须严格等于待释放商品件数；不一致则整笔回滚。
5. 保存商品实际数量及确认审计，设置 `packing_plan_status=ACTUAL_CONFIRMED`。
6. 写入操作账本和释放摘要，保证重复确认不重复释放。

确认后箱间重新分配只能保持每种商品的汇总等于已确认实际任务量。若确需补装已释放数量，必须回到库存绑定/拣货链路重新建立库存事实，本期称重页面不提供补锁入口。

## 称重完成

单任务完成条件：

- 至少一个有效箱。
- 每个有效箱至少包含一个商品。
- 每个箱的重量、长、宽、高全部大于 0。
- 每种商品的箱内任务量汇总等于其允许装箱任务量；未做部分确认时等于原 `task_qty`，部分确认后等于 `actual_packed_task_qty`。
- 库存分配商品件数与 `actual_packed_required_qty` 一致。

全部条件在后端事务内重新验证后，将任务设为 `COMPLETED`。一张 WMS 拣货单的全部有效装箱任务均完成后，订单才从 `WEIGHING` 进入 `PENDING_OUTBOUND`。前端按钮禁用仅用于提示，不能代替后端校验。

## 接口契约

称重链路增加或调整以下任务级接口：

- `GET /dispatch-workflow/{orderId}/packing-tasks/{taskId}/packing-plan`：返回商品池、有效箱、箱内商品、草稿状态和可执行动作。
- `PUT /dispatch-workflow/{orderId}/packing-tasks/{taskId}/packing-plan`：保存完整草稿快照。
- `POST /dispatch-workflow/{orderId}/packing-tasks/{taskId}/confirm-actual`：确认实际装箱并释放余量。
- 现有 `complete-weighing`：改为按新完整性与库存一致性规则完成任务。

旧的单箱测量保存接口保留兼容读取，但新页面只使用任务级草稿接口，避免箱尺寸已保存而商品分配未保存的半成品状态。

## 并发、异常与兼容

- 所有写操作同时校验订单、任务和相关行版本；冲突返回 `CONCURRENCY_CONFLICT`，前端刷新后重试。
- 来源变化冻结沿用现有裁决机制，冻结期间禁止保存草稿、确认实际和称重完成。
- 已进入 `PENDING_OUTBOUND` 或后续状态的数据只读。
- 已存在的 `WEIGHING` 记录保留现有 WMS 占位箱，首次保存新草稿时可编辑或删除；不再要求 SellFox/FBA 箱身份。
- 历史 FBA 表和历史出库事实不迁移、不回填。

## 验收边界

本轮按用户要求只做静态验收，不启动、停止或重启开发服务，不执行数据库迁移，不运行长测试。

静态验收至少检查：

- 前后端 DTO、API 路由与状态字段一致。
- 迁移脚本为仅追加的 `wms_` 表/字段且可重复由 Flyway 管理。
- 草稿保存路径不修改库存。
- 实际确认路径在单事务内固化数量并释放余量。
- 所有装箱输入和校验只控制 `task_qty`；变体直接展示，商品件数和库存调整量自动换算。
- 不同装箱任务无法共享箱或箱内商品。
- 只有全部箱规、重量、商品和数量完成后才允许进入待出库。

## 自审

- [x] 不同装箱任务绝不混装，同任务商品允许混装。
- [x] 装箱依据为任务量，商品需求量只用于展示和库存事实。
- [x] 变体在创建时固化，称重时只读展示，其余商品数量自动计算。
- [x] 草稿保存与实际确认是两个独立动作。
- [x] 草稿允许不完整且不释放库存。
- [x] 实际确认明确提示余量并原子释放库存。
- [x] 释放后禁止在称重页补回数量。
- [x] 箱规、重量、商品选择和数量全部完整后才能完成称重。
